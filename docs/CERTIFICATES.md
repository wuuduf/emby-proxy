# 多线路证书自动化实施规格

目标：业务 A 记录不切换，备用节点也能先具备有效 HTTPS。Cloudflare Token 只留主控，边缘通过已验证的 HTTPS + 节点令牌领取所属入口证书。共享入口私钥；不签通配符，不给边缘 DNS 权限。DNSPod/其他 DNS 的控制面证书由已有 Caddy 通过 HTTP-01 管理，不需要把 DNS 凭据发给边缘。

验证边界：控制器证书 API（TLS、鉴权、入口隔离）；边缘安装/同步（校验、原子替换、reload 回滚）；CLI 与菜单操作。使用本地测试证书与模拟 Cloudflare/Certbot，不操作真实 VPS/DNS。

实施顺序：
1. 受认证的 TLS 证书领取 API；HTTP 禁止领取，禁止重定向传递令牌。
2. Cloudflare 使用 DNS-01 签发入口和独立主控域名证书；DNSPod/其他 DNS 使用 Caddy 443 反代到 `127.0.0.1:19090` 并自动 HTTP-01 续期；两者都不改业务 A 记录。
3. 边缘外部证书安装、独立同步定时器、本机健康检测与回滚。
4. 菜单配置/状态入口、回归和审查。

Cloudflare 模式控制器内建 TLS，独立端口默认 19090；Caddy 模式控制器只监听本机 19090，由 Caddy 接管已运行的 443 站点配置。首版主控域名 A 记录需预先指向主控，菜单明确检查/提示；不自动覆盖已有 DNS 记录。Caddy 配置写入前备份、格式化、校验和 reload，遇到非托管同域站点拒绝覆盖。

失败边界：签发失败保留已有证书；下载、校验、reload 失败保留/恢复旧版本；主控离线不影响已有有效证书；旧 HTTP 控制面不能领取私钥。只在开启集中证书功能后要求注册使用 HTTPS，保留旧部署兼容。

不能宣称：未做真实 ACME、systemd、Caddy/Nginx 或 VPS 演练前，不算生产验收。CA staging 验证与证书续期/节点故障组合实测另行授权。

已实现：DNS-01 Certbot 编排、Caddy HTTP-01 控制面、节点鉴权领取、私钥校验与原子版本目录、独立续期/同步定时任务、菜单 8/9、状态展示与带托管标记的卸载清理。
审查后修复：HTTPS 注册要求移入锁内校验；配置主控失败恢复协议字段；节点重装失败恢复旧证书指针。
验证证据：本地真实 TLS（临时自签信任根）验证下载与拒绝不可信 CA；Certbot/systemd 用替身测试；DNSPod 测试 VPS 已验证 Caddy 443 → 127.0.0.1:19090、Let’s Encrypt 证书、HTTPS `/status` 和边缘心跳。仍需按实际 DNS TTL 做上线验收。
