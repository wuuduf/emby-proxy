# 主控与边缘节点配置设计

> 这是一份配置流程设计稿，不代表所有阶段已经在当前版本上线。它把用户真正需要做的事、脚本自动完成的事，以及失败后如何继续，先固定下来，再按阶段实现。

## 1. 设计目标

多线路的难点不是 DNS API，而是控制面、边缘节点、证书和业务域名之间的依赖容易被拆散。当前版本需要用户记住“配置入口 → 配 HTTPS → 启动主控 → 生成节点命令 → 再去配置 DNSPod/权重”，任何一步失败都只能从菜单猜下一步。

新流程遵循四条原则：

1. **普通用户只填业务信息**：对外域名、固定源站、DNS 提供商、地址族；主控域名、入口 ID、节点 ID、引擎和公网 IP 自动派生。
2. **一个入口只有一个继续按钮**：每次打开菜单先读取状态，定位到唯一的下一步；失败后从失败步骤继续，不清空已经确认的输入。
3. **计划与应用分离**：先做只读预检，再显示将要修改的文件、服务和 DNS，用户确认后才写入；写入后必须回读验证。
4. **注册成功不等于可以切流**：节点必须分别经过“已注册、反代已安装、证书就绪、心跳正常、DNS 已确认”这些检查，面板只在最后一步标记“可切换”。

主控只负责注册、心跳、选路和 DNS 更新，不转发媒体流量。媒体始终是“客户端 → 当前边缘 → 固定源站”。

## 2. 角色和不可变契约

### 主控

- 保存一个入口的业务域名、固定源站、地址族、引擎和 DNS Provider；
- 保存节点注册票据、节点状态、期望 DNS 和已回读 DNS；
- 周期性执行 `plan → apply → verify`；
- 不接收客户端的媒体请求，不提供未认证的公网 DNS 变更接口。

### 边缘节点

- 运行 Caddy 或 Nginx，承载真正的 HTTPS 反代；
- 向主控发送心跳、累计响应字节和可选的有限指标；
- 只使用主控下发的固定源站，不允许客户端通过 URL 指定任意公网目标。

### 入口契约

一个入口一旦开始注册节点，以下字段默认不可原地改变：

| 字段 | 规则 |
| --- | --- |
| 对外域名 | 自动生成入口 ID：`domain-<小写域名>` |
| 固定源站 | 所有边缘使用同一个源站和 Host/SNI |
| 地址族 | `ipv4` 使用 A，`ipv6` 使用 AAAA；不能在同一入口混用 |
| 引擎 | 自动复用主控已运行的 Caddy/Nginx；边缘必须一致 |
| 控制域名 | 自动建议 `control.<业务域名>`，不能与业务域名相同 |

需要更换域名、源站或地址族时，优先“复制为新入口、滚动添加节点”，而不是清空旧入口。

## 3. 新菜单布局

普通用户看到的是概念，不是内部命令编号：

```text
多线路控制器

当前阶段：控制器已就绪，等待添加边缘节点
下一步：选择 2，在另一台 VPS 执行生成的节点命令

1  开始/继续部署       自动执行当前缺失步骤
2  添加边缘节点         只填写备注和配额
3  节点与注册任务       查看心跳、证书、待领取票据、重发/撤销
4  DNS 与流量策略       主备、DNSPod 线路、计划；显示预览后再应用
5  证书与主控地址       主控 HTTPS、备用节点证书、续期状态
6  诊断与服务           预检、systemd、端口和最近错误
7  备份、迁移与恢复     复制入口、恢复快照、清理失败注册
8  高级设置             监听地址、检查间隔、实验性功能
9  Telegram 通知        可选的只读查询和告警
0  返回
```

旧版 `controller init/issue/node-install/reconcile` 和旧菜单编号继续保留为兼容入口，但不再作为新手教程的主路径。入口存在时，选 1 应显示“继续部署”，而不是再次进入破坏性的初始化。

## 4. 主控一键部署向导

### 4.1 普通流程只问四项

```text
1. 对外域名：emby.example.com
2. 固定源站：https://origin.example.com:8443
3. DNS 提供商：Cloudflare / DNSPod / 稍后配置
4. 地址族：IPv4 / IPv6（默认 IPv4）
```

以下值自动处理：

- 入口 ID：按域名生成；
- 引擎：复用当前运行中的 Web 服务，没有则默认 Caddy；
- 控制域名：默认 `control.<业务域名>`，只有冲突时才要求修改；
- 主控监听：`127.0.0.1:19090`；
- 检查间隔：30 秒；
- DNS Zone ID、Record ID：按域名和 Token 自动发现；
- 节点 ID、公网 IP：在边缘侧自动生成和检测。

### 4.2 向导阶段

每一步写入 `setup_step`，中断后可以继续：

```text
DRAFT
  → ENTRY_SAVED       已保存域名和源站
  → PROVIDER_READY    DNS 凭据/记录/NS 预检通过
  → CONTROLLER_READY  主控服务和 HTTPS /status 可访问
  → NODE_PENDING      已生成待领取节点票据
  → NODE_READY        至少一台边缘通过证书、心跳和本机健康检查
  → DNS_CONFIRMED     DNS API 回读与期望节点一致
  → READY             入口可切换
```

向导每个阶段都输出三块信息：

```text
[已完成] 已保存业务域名和固定源站
[待处理] control.example.com 需要指向主控 VPS
[下一步] 放行 TCP 80/443 后按回车继续预检
```

Cloudflare 原生 TLS 和 DNSPod/Caddy 443 的实现差异隐藏在步骤内部。用户只需要看到最终的“主控访问地址”，不再手工判断 `19090` 还是 `443`。

### 4.3 预检、计划、应用

在任何写操作前依次执行：

1. **预检**：DNS/NS、凭据权限、Caddy/Nginx 冲突、端口占用、源站可达性；
2. **计划**：列出会修改的状态文件、Caddyfile/Nginx 片段、systemd 单元和 DNS 记录；
3. **应用**：备份 → 写入 → validate → reload/restart → 回读；失败恢复备份并记录 `last_error`。

预检失败不能生成公网 HTTP 注册命令。HTTP 只允许显式的 loopback/WireGuard 高级模式，并在票据上标记 `insecure=true`。

## 5. 添加边缘节点

### 5.1 主控侧只问两项

```text
节点备注（可留空，默认“边缘节点 1”）：香港
流量配额（默认不限额）：0 / 500 GB / 1 TB
```

优先级默认按已有节点递增（第一台 100，下一台 90）；需要精细调度时才展开“高级选项”。地址族、引擎、控制器 URL、公网 IP 都从入口状态派生，不再重复询问。

生成前显示一页计划：

```text
入口：emby.example.com
固定源站：https://origin.example.com:8443
主控：https://control.example.com
边缘契约：Caddy · IPv4 · HTTPS 443
备注：香港 · 优先级 100 · 配额 500 GB

确认后生成 15 分钟有效的一次性注册票据？[Y/n]
```

### 5.2 票据而不是裸参数

主控保存待领取票据时绑定：入口代数、节点 ID、备注、优先级、配额、地址族、引擎和过期时间。边缘命令只携带控制器地址和一次性票据；不再把这些可变参数交给边缘自行提交。

菜单支持：

- 查看未领取票据和剩余时间；
- 重新显示同一票据（不重新覆盖节点）；
- 撤销票据；
- 票据过期后重新签发；
- 对同一节点显式选择“替换”，而不是静默覆盖旧票据。

票据只在完整的边缘预检通过后才消费。预检包括 root/systemd/curl、已有节点状态、Caddy/Nginx 冲突、地址族、公网 IP、端口和主控 `/status` 能力版本。

### 5.3 边缘执行顺序

```text
只读预检
  → 下载安装/更新管理器
  → 本地生成候选反代配置
  → 本地 validate
  → POST /enroll/commit 消费票据
  → 写入节点状态
  → 安装/启动心跳 timer
  → 首次 heartbeat
  → 请求证书并切换 current
```

任何步骤失败都回滚本地文件和 systemd；远端节点保持 `needs_cleanup`，主控菜单提供“清理失败注册”。“已注册”只表示控制面接受了票据，不表示已经可以切流。

为兼容旧版本，`/enroll` 和长版 `node-install` 暂时保留；菜单生成的新命令使用新票据协议，旧命令显示“兼容模式”。

## 6. 状态模型

### 6.1 入口状态

```text
draft → configured → controller_ready → provider_ready → serving
                                             ↘ degraded
```

`desired` 表示状态机想写入的节点，`applied` 表示 DNS API 全量回读后确认的节点。两者不能混用：任一条记录更新失败时只写 `degraded/last_error`，不能更新 `applied`。

### 6.2 节点状态

```text
issued → enrolling → provisioning → probing → healthy
                                      ↘ suspect → unhealthy
healthy → exhausted       （配额达到）
healthy → draining         （人工停用）
任意状态 → revoked
```

节点状态拆成三块：

- `policy`：是否启用、优先级、配额；
- `observed`：最近心跳、服务进程、本机 HTTPS、证书、源站探测结果；
- `registration`：票据代数、安装事务、最近错误和清理状态。

只有 `healthy + online + quota_ok + engine/family 匹配` 的节点才能进入 `desired`。心跳正常但证书未就绪的节点应显示“已注册，暂不可切换”，而不是“健康”。

### 6.3 schema 迁移

读取旧 `schema_version=1` 时：

1. 先创建带 SHA256 的备份；
2. 保留已有节点、注册码和 DNS 记录；
3. 映射到 `entry/control/provider/policy/nodes/audit` 分区；
4. 写入 `schema_version=2` 和 `setup_step`；
5. 任何字段无法安全映射时停止，不清空旧状态。

## 7. DNS 与策略的简化

### 默认模式：主备切换（推荐）

普通 Cloudflare DNS 只维护一条 A/AAAA，按优先级选择一个健康节点。这是默认且最容易解释的模式。

### DNSPod：运营商线路

DNSPod 只在用户明确选择“运营商分流”时显示。向导先检查 NS 委派和四种线路记录，再让用户为线路绑定节点。每条线路失败独立显示，不把“全部成功”写在部分成功上。

### 权重和定时

普通 Cloudflare DNS 不能可靠表达精确的 80/20：重复同 IP 记录会被 API 拒绝，多个 DNS 记录也会受 TTL 缓存影响。因此：

- 普通菜单默认隐藏 Cloudflare 权重；
- 高级菜单明确标为“记录槽位近似”，不能宣传为精确比例；
- 精确权重应接入 Cloudflare Load Balancing 或原生支持权重的 DNS Provider；
- 定时策略必须有全天候 base profile，时间档位只是覆盖层，并显示主控本地时区。

## 8. 证书和主控地址

证书是节点能否进入 `desired` 的硬条件：

- Cloudflare：主控使用 DNS-01，边缘可从主控领取入口证书；
- DNSPod/其他 DNS：主控使用 Caddy HTTP-01；边缘在切换前必须持有有效入口证书；
- 证书更新使用版本目录和 `current` 原子切换，校验/重载失败保留旧版本；
- 主控 URL 由 DNS Provider 和证书模式派生并保存，节点向导不再手填端口。

## 9. 日常故障恢复

面板首页只给一个动作：

```text
主控 HTTPS 已就绪，但没有可切换节点。
下一步：2 添加边缘节点
```

典型问题的处理路径：

| 现象 | 用户操作 |
| --- | --- |
| 主控 URL 不通 | 6 → 预检；按提示修 DNS/80/443/证书 |
| 票据过期 | 3 → 待处理票据 → 重新签发 |
| 边缘有 Caddy/Nginx 冲突 | 边缘预检显示现有服务；选择复用同一引擎或取消，不自动卸载 |
| 节点已注册但不可切换 | 3 查看缺失项：证书、心跳、本机健康或配额 |
| DNS 部分写入 | 4 → 立即同步；先回读，失败保留 `applied` 并重试 |
| 更换源站/域名 | 7 → 复制为新入口；旧入口继续服务直到新入口验收 |

## 10. 分阶段实施

### P0：不改媒体链路，先改向导

- 新增可恢复的“开始/继续部署”；
- 自动派生控制域名、主控 URL、引擎、地址族；
- 节点向导只问备注和配额；
- 首页显示 `setup_step` 和唯一下一步；
- `controller init` 改为非破坏性编辑，重置单独确认。

### P1：票据和事务

- `pending registration` 和注册代数；
- 边缘 `preflight → commit`，失败可清理；
- 待领取票据可查看、撤销、重发；
- 公网模式拒绝 HTTP 注册。

### P2：状态和 Provider 收口

- schema v1 → v2 迁移；
- `desired/applied` 与逐线路错误；
- 显式节点生命周期；
- 普通 Cloudflare 隐藏伪权重。

### P3：高级能力

- 控制器同时作为边缘的独立实例模式；
- 精确权重 Provider；
- 账期配额、时区/DST、Telegram 高级告警。

每个阶段都必须同时覆盖菜单、CLI、失败返回和恢复路径；通过本地测试后，再做授权 VPS/DNS 验收。未经验证的阶段不在 README 中宣称“已支持”。
