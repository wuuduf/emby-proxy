# 行为约束与验收条件

本文件记录必须保持的行为，不把愿望当作已上线能力。

## 稳定入口
- 第一次无参数运行先进入菜单，不直接开始配置域名。
- `ep` 与 `emby-proxy` 打开同一管理菜单；CLI 仍可直接调用。
- 仅域名 HTTPS：独立子域名、独立 HTTPS 端口、显著警告的子路径兼容模式。
- 独立端口必须提醒防火墙/安全组放行。
- 子菜单输入错误、取消、操作内部退出不能带着整个面板退出。
- 更新成功且内容变更：交互终端重新打开新管理器；非终端只提示，不启动无限菜单。
- 同版本号内容更新也算更新；未变化/取消/失败不触发重启。

## 安全修改
- 仅操作明确属于本项目的托管配置；不能把“文件名类似”当作删除授权。
- 写操作前保留备份；候选配置无效不应用；reload 失败恢复旧配置。
- 固定回源 Host，不能继承用户提交的伪造 XFF 链，不能关闭上游 TLS 验证。
- 对外 `/_emby_proxy_health` 返回 200 只证明该健康路由可用；路径反代收到源站任意 1xx-5xx 响应即显示“反代验证通过（链路可达）”，但 403/404/503 仍不能证明业务接口或媒体可播放。
- 报告应区分：语法有效、配置可加载、HTTPS 可达、业务接口有效、真实媒体可播放。

## 多线路实验验收
- 注册码只能用一次；错误入口/令牌不得建立节点。
- 高优先级且健康、最近有心跳、未超额的节点优先。
- 当前过期门槛为 90 秒；用量等于配额即不可选；0 配额表示不限。
- 同一节点回报更小累计用量不得使计数倒退。
- DNS 写入后必须 API 回读确认所选地址类型记录（A 或 AAAA）的域名、IP、灰云状态；失败保留最近确认的活动节点，下次仍可重试。未配置 DNS 不得宣称切换成功；当前节点 IP 变化也要重新同步。
- 主控入口固定一个地址族：`ipv4` 使用 A 记录，`ipv6` 使用 AAAA 记录；边缘注册、心跳、DNS 更新和本机健康检查必须使用同一地址族，不能在同一入口混用。
- 边缘地址族选择必须在注册码中绑定；自动检测必须使用对应的 `curl -4`/`curl -6`，手动地址必须通过对应 IP 类型和公网地址校验。
- DNSPod 线路模式只能接管明确发现的 `默认/电信/联通/移动` 四种线路的启用 A/AAAA 记录（随入口地址族）；每种线路允许一条或多条同线路记录。必须校验区域、子域、记录 ID、线路 ID、类型、状态和无监控，修改后逐条 `Record.Info` 回读确认；记录自带权重不作为本脚本的分配依据。父域 NS 委派只读检查，不能由脚本替用户修改。
- DNSPod 每条线路允许显式指定节点；指定节点不健康、失联或超额时回退到该时刻健康候选。线路成功/失败独立持久化，不能因一条线路失败宣称全部切换成功。
- DNSPod 同一线路存在多条记录时允许配置节点权重；按记录槽位做确定性分配，健康/配额筛选优先于权重，任一记录回读失败都保留待确认状态并单独重试。
- Cloudflare/DNSPod IPv6 模式只接管 AAAA 记录；发现冲突的 A/AAAA/CNAME 记录时必须停止，避免双栈绕过控制器的切换策略。
- Cloudflare 至少两条同名 A/AAAA 记录时允许启用权重池；必须保存全部 record ID，按权重展开到记录槽位，逐条更新并回读。任意记录更新失败都保留 `dns_needs_confirmation`，下一轮重试，不能把部分成功宣称为完整切换。
- 定时策略按服务器本地时间选择最近一个已开始的档位，跨午夜沿用前一天最后档位；时间重复、格式错误、未注册节点必须拒绝保存。计划切换仍经过健康/心跳/配额筛选，不能把不健康目标直接写入 DNS。
- 连续 3 次自报失败才下线；新节点/恢复节点需至少 3 次连续成功且持续 60 秒。失联恢复必须重新观察。
- 健康节点间抢占冷却 180 秒；同优先级保留当前节点；失联、确诊故障、超额不受冷却阻挡。故障观察中的备用节点不提升。
- 边缘先检查已有 Caddy/Nginx，再注册；引擎冲突必须在消费注册码前拒绝，不能为了安装节点改动其他引擎。
- Telegram Bot 只允许主控出站长轮询 Telegram API，不开放入站监听；Bot Token 必须独立 `600` 文件保存，命令必须匹配白名单 Chat ID。
- 边缘心跳可附带最近窗口聚合指标，字段和数组必须限长、限数值范围；只保留请求数、字节、错误数、访问 IP、粗粒度设备类别和路径，不上传 Token、完整查询串或原始日志。
- Bot 查询必须是只读命令：状态、节点、流量、访问 IP、设备、源站；未知命令拒绝执行，通知发送失败不能影响 DNS/节点主流程。
- 失败/恢复计数与冷却时间持久化；菜单说明等待原因，无可用节点时明确警告。
- 自动节点 ID 避开已注册节点和待使用注册码中的 ID。
- 配额菜单支持单位与数值，内部统一为字节。
- 控制器状态文件必须是 0600；已有状态禁止无确认覆盖，`--force` 才能重建并先生成备份。
- 注册码必须一次性使用并有有限 TTL；过期注册尝试不能建立节点。
- 边缘健康必须同时通过 Web 服务进程检查和本机 HTTPS 健康路径；TLS 校验不能用 `-k` 绕过。
- 不提供未认证的公网 `/reconcile` 变更接口；周期主控直接在本地调用选路状态机。
- 边缘用量从托管 JSON 访问日志增量读取，日志 inode/偏移必须持久化，健康路径不能计入配额；读取失败不能让已有用量倒退。

上面是局部状态机验收，不代表自动流量采集、公网证书分发、控制面安全或播放器无缝切换已实现。缺口见 WORKLOG。

## 可选集中证书验收
- 注册领取证书必须真实 HTTPS；节点令牌与入口身份匹配；禁止重定向携带凭据。
- DNS-01 仅更新验证 TXT，不为申请证书切换业务 A 记录。Cloudflare Token 只保留主控。
- 证书校验通过才发布；重载失败恢复旧版本，不能放宽 TLS 验证。
- cert-setup 失败不能把原 HTTP 主控配置留在错误 HTTPS 状态；签发与同步独立于心跳。
- DNSPod/其他 DNS 的 `https-proxy-setup` 必须拒绝覆盖非脚本托管的 Caddy 站点；写入前备份，`fmt/validate/reload` 任一步失败恢复 Caddyfile 和状态，成功后控制器仅监听 `127.0.0.1:19090` 并用公开 HTTPS `/status` 验证入口身份。
- 不使用其他服务证书目录，不移除非托管文件；测试通过不代表真实 CA 或 VPS 已验收。
