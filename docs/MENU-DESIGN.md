# 菜单交互约定

目标：先看状态，再决定操作；普通用户填业务信息，技术参数使用明确的默认值。
不为了减少一个问题而自动暴露控制端口、覆盖已有入口或跳过检查。

## 主面板

保留原 1–12 编号，不改变 CLI。首页只显示本机入口数量、引擎分布、服务状态和下一步，
不执行远端健康探测、不打印版本哈希或原始 socket 列表。详细信息仍由 `ep status`、诊断和服务菜单提供。

- 入口配置：1 列表、2 详情、3 新增、4 管理。
- 观察与维护：5 诊断、6 日志/统计、7 备份、8 Web 服务。
- 扩展与工具：9 导入、10 更新、11 多线路。
- 独立的卸载区域：12；继续保留原确认和托管范围限制。
- 0/q 返回或退出；EOF 正常返回，避免在脚本输入结束后循环刷屏。

标签不再用按字节计算的固定宽度填充，避免中文与英文混排错位。

## 普通反代

维持已有四步：选择/确认引擎 → 入口结构 → 访问域名 → 固定源站。
回车使用 Caddy（没有已有引擎时）与独立子域名 + 443；仅端口模式问端口，
仅高级路径模式问额外路径。已有服务的确认、备份和配置校验不能省略。

## 多线路

```text
1 配置主控入口     域名、源站、自动选择引擎、是否启用 Cloudflare
2 启动主控服务     自动使用 127.0.0.1:19090、30 秒
3 添加边缘节点     主控 URL → 连通性/入口匹配 → 自动检测 IP

4 节点状态与用量   人类可读，不把原始 JSON 当面板
5 立即同步 DNS     沿用现有选路机制
6 服务状态与日志
7 高级主控参数     仅需要自定义监听/检查间隔时使用
0 返回上一级
```

- 状态路径默认 `/etc/emby-proxy/controller.json`，不在向导中提问。
  高级用户仍可用环境变量 `EMBY_PROXY_CONTROLLER_STATE` 或 CLI `--state`。
- 域名统一小写，入口 ID 自动生成；源站没填协议时使用 HTTPS。
- 边缘引擎不再重复询问：优先复用正在运行的 Caddy/Nginx，没有已安装引擎时默认 Caddy；
  高级用户仍可用 CLI `controller init --engine` 显式指定。
- Cloudflare Token 只在首次启用时输入一次；之后检测到本地 `600` 权限 Token 会自动沿用，
  仍会重新按域名校验 Zone 和 A 记录。
- 配置已存在先提示风险并默认取消；新增节点不需要重新初始化。
- 主控服务直接使用安全默认值 `127.0.0.1:19090` 和 30 秒，不再为普通用户提问；
  高级用户可用 CLI `controller master-install --listen ... --reconcile-interval ...` 修改。
- 节点公网 IPv4 优先通过 `api.ipify.org` 自动检测，失败时才要求手动填写。
- 节点 ID 由主控自动生成且避免冲突：CLI 提供 IP 时使用可读的 `edge-<ip>`，菜单默认使用
  `edge-node`、`edge-node-2` 等序号；名称默认用 ID，优先级默认 100，配额默认不限额；
  只有选择“修改名称、优先级或配额”时才进入高级字段。
- 配额高级字段一个输入框：`500GB`、`1.5TB`、`2 gb`；纯数字按 GB，回车/0 不限额。
  沿用二进制换算（1 GB = 1024³ bytes），状态面板显示 GiB/TiB 避免歧义。
- 主控地址第一次填写；成功生成命令后在现有状态锁内记住地址，后续节点自动沿用并先做连通性检查，
  失效时才要求重新填写。该记忆值不是凭据，不另建配置文件。
- 字段支持 q 取消和原地重填；连通性/入口身份检查在节点问题之前，避免白填一遍。
- 启动后直接展示 systemd 状态，不再多问“是否查看”。首次启动使用上述默认值；
  再次启动只启动已有主控单元，不改写其参数；需要自定义时进入 7。systemctl 失败不显示成功，
  且不会重启 Caddy/Nginx。

## 不能隐藏的边界

控制器 HTTPS 入口仍需配置，本轮没有实现自动证书/安全控制面部署。
首页与节点面板明确标注实验版。心跳会检查进程和本机 HTTPS 健康路径，配额来自托管 JSON
访问日志的累计响应字节；DNS 切换不等于播放器无缝迁移，也不等于逐请求负载均衡。
